# Filters use the compact `key:value` syntax

A Filter is written in the compact syntax familiar from GitHub and Gmail: `tag:rust status:raw,active -has:effort "borrow checker"`. Juxtaposition is AND, `-` negates, `or` (any case) and parens are the rare escape hatch, `key:a,b` is any-of, `has:` tests presence, `title:`/`body:` scope a text term, and bare words are text terms. Dates are periods (`created:2026-09`) or inclusive `..` ranges whose ends may be relative instants (`updated:..90d`, `updated:90d..`); there are no `<`/`>` operators. The filter is one opaque string parsed only by the server, so the open thoughts untouched for three months are `status:raw,active -updated:90d..`.

The syntax was chosen because the filter's main home is the command line after `thought ls`, where positionals are joined by spaces: nearly every realistic filter types bare, with no shell quoting, and the agents' pre-capture search is just a few words and a tag (`borrow checker tag:rust`) with no grammar to learn. Ranges rather than `<`/`>` keep dates shell-safe and sidestep the "before the instant 90 days ago" versus "less than 90 days old" ambiguity. The costs: a forgotten quote silently changes meaning (`source:shower thought` is `source=shower` plus the text `thought`), a typo'd key is a valid filter that matches nothing (the CLI prints a vocabulary hint on an empty result), `has` becomes a reserved key, and `:` means equality on attributes, containment on dates and text match on `title`/`body`. Full detail is in the [Filter language](https://github.com/NurramoX/ideation/issues/6) resolution; the candidates were tried side by side in the throwaway `prototype/filter-language` branch.

## Considered options

- **LDAP-style `(&(tag=rust)(!(effort=*)))`**: the smallest unambiguous grammar and trivial to generate, but every filter needs shell quotes, the simplest filter is not simple, text has no natural home because `text` is a legal attribute key, and without strict `<`/`>` the open thoughts untouched for three months become `(&(|(status=raw)(status=active))(!(updated>=90d)))`.
- **Expression syntax `tag = rust and not has effort`**: reads like a sentence and gives the best parse errors (a stray word is an error, not a text term), but explicit `and` everywhere is verbose for the everyday two-tags-and-a-status filter, and quoted text, `in (...)`, parens and `<`/`>` put two thirds of realistic filters in shell quotes.
- **Compact with `<`/`>` date operators instead of ranges**: `updated:<90d` looks natural but is a shell redirect unquoted, and forces a choice between the instant and the age reading of a relative value.
